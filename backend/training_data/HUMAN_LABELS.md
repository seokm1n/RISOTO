# 사람 라벨 정답지

관련성 필터와 위기 탐지를 평가하기 위해 사람이 직접 만든 정답지입니다.
2026-09-02 ~ 09-03 작업분이며, 이 저장소에서 **사람이 만든 유일한 관련성 라벨**입니다.

## 왜 필요한가

기존 `article_labels` 2,163건은 **전부 LLM 생성분**이고(`annotator LIKE 'llm:%'`) 사람 라벨은 0건이었습니다.
그래서 그동안의 필터 성능 수치는 "정확도"가 아니라 "필터와 LLM의 불일치도"였습니다.

측정해 보면 LLM 라벨이 사람보다 부정확합니다.

| 기준 | relevance_score AUC |
|---|---|
| 사람 라벨 | **0.718** |
| LLM 라벨 | 0.639 |

**모델 평가나 재학습에 LLM 라벨을 정답으로 쓰면 더 나쁜 목표를 향해 최적화됩니다.**

## 파일

### `human_relevance_labels.csv` (600건)

기사 한 건이 그 기업에 관한 내용인지 사람이 판정한 것입니다.

| 컬럼 | 설명 |
|---|---|
| `round` | 1차(300) / 2차(300) |
| `stratum` | 표집 층 (아래 참조) |
| `raw_article_id` | `raw_news_articles.id` |
| `company_id` | `companies.id` |
| `relevance_label` | `relevant` / `incidental` / `irrelevant` / `uncertain` |
| `advertisement_label` | `yes` / `no` / `uncertain` |
| `decision`, `relevance_score` | 라벨링 당시 필터의 판정 (비교용) |

분포: irrelevant 366 · relevant 158 · incidental 54 · uncertain 22

### `human_risk_event_labels.csv` (82건)

위기 사건 하나가 실제로 대응이 필요했던 위기인지 판정한 것입니다.

| 컬럼 | 설명 |
|---|---|
| `event_id` | `risk_events.id` |
| `is_risk` | `TRUE` / `FALSE` / `UNCERTAIN` |
| `실제유형` | 8유형 중 해당되는 것 전부, 중요한 순서로 쉼표 구분 |
| `제목에기업명` | 근거 기사 중 제목에 기업명이 있는 개수 |
| `band`, `max_p` | 사건의 최대 위기확률 구간 (비교용) |

분포: TRUE 36 · FALSE 44 · UNCERTAIN 1 · 미기입 1

## 표집 방법

무작위가 아니라 **정보량 기준 층화**입니다. 같은 건수로 더 많은 것을 알기 위해서입니다.

| 층 | 무엇을 알 수 있나 |
|---|---|
| `A_확신통과` (score ≥ 0.90) | 통과분의 오탐률 |
| `B_확신거절` (score ≤ 0.10) | 거절분의 누락률 |
| `C_경계` (review_required) | 보류 구간이 실제로 애매한지 |
| `D_중간대역` | 중간 점수대 판별력 |
| `E_커뮤니티` | 커뮤니티 게시글의 유효성 |
| `F_플랫폼기업` (2차) | 네이버·카카오가 더 어려운지 |

**학습 오염을 막기 위해** 배포 모델 생성 시각(2026-08-26 11:00) 이후 수집분, 기존 라벨이 없는 기사만 사용했습니다.
따라서 현재 배포된 어떤 모델도 이 기사들로 학습되지 않았습니다.

## 판정 기준

「위기 사건 라벨링 규칙」 문서를 따랐습니다. 요약하면:

- **위기 판정** — 개인 푸념 한 건은 위기가 아니고, 대응이 필요했던 사건이어야 합니다.
  같은 주제로 여러 건 모이면 여론으로 봅니다
- **유형 선택** — "어느 유형의 대응 지침이 이 사안에 실제로 쓸모 있나"로 고릅니다.
  평판 영향이 있어도 쓸 지침이 없으면 붙이지 않습니다
- **관련성** — "기업명이 나오는가"가 아니라 **"그 기업에 대해 무엇을 말하는가"**로 봅니다.
  수단·장소·경품·판매처로 이름만 스쳤으면 `irrelevant`

기준이 바뀌면 새 라운드로 분리하고 이전 라벨과 섞지 마세요.

## 이 정답지로 측정한 현재 성능

관련성 필터 (578건, `review_required` 제외):

```
정확도 58.0%   정밀도 48.7%   재현율 72.8%
AUC 0.7182
```

**통과시킨 것의 절반 이상이 무관 기사입니다.** 가장 큰 원인은 통과분의 60%가
"본문에만 기업명이 있는" 기사이기 때문입니다 — 제목에 있으면 유효율 71%, 본문에만 있으면 32%입니다.

위기 탐지 (이벤트 그룹 층화 K-fold, out-of-fold):

```
Brier 0.0229   AUC 0.9956   재현율 0.837
```

기존 시간순 분할은 양성 사건 23건이 전부 앞 70%에 몰려 **검증 구간이 100% 음성**이었습니다.
저장된 확률로 잰 값(Brier 0.00786)은 2.9배 낙관 편향입니다.

## 주의

- `uncertain` 22건은 평가에서 제외하는 것을 권합니다
- 라벨러 간 일치도는 아직 측정하지 않았습니다(단일 작성자). 20% 교차 라벨이 다음 과제입니다
- 위기 라벨의 양성은 36건입니다. 재학습 하한(양성 20 / 음성 60)에 가까우므로
  라벨을 재분류할 때 양성이 줄지 않는지 확인하세요
